회사에서 Salesforce로 만든 것들

고3 때 DKBMC에 Salesforce 개발자로 입사했습니다. 첫 업무로 OData 4.0 작업을 시작했고, 이어서 SRM 공급자 등록 요청을 개발한 뒤 SRM 전체를 맡게 되었습니다. 그 과정에서 반도체 제조 고객사 구축, 사내 솔루션 고도화와 패키징, AI 에이전트와 MCP 서버까지 경험하며 역량을 넓혀 가고 있습니다. 카드를 누르면 구현 내용이 펼쳐집니다.

회사 코드는 공개할 수 없어, 각 저장소에는 정리 문서와 핵심 구조를 직접 다시 구현한 예제 코드를 담았습니다. 고객사와 사내 제품명은 일반 표현으로 바꿨습니다.

AI Agent · MCP2026.08 – 10

SRM AI 에이전트 + Salesforce MCP 서버

"이 공급사 견적 비교해 줘" 같은 말로 구매 업무를 조회 · 실행하는 에이전트를 만들고, Claude 같은 외부 AI가 원격 커넥터로 SRM을 쓰도록 MCP 서버를 Apex로 직접 구현했습니다.

MCP 프로토콜 직접 구현0 브라우저 노출 API 키
Azure OpenAIMCPFunction CallingStructured OutputsOAuth
  • 보안 구조 전환 — 브라우저 WebSocket 방식에서 서버 측 Chat Completions로 바꿔 API 키가 브라우저에 노출되지 않게(Named / External Credential)
  • 도구를 데이터로 — 도구 정의를 레코드 · Custom Metadata로 관리하고, 범용 실행기 3종(연쇄 조회 · 비교 · 필터 목록) + 스키마 가드(describe 재검증)로 동적 SOQL 보안 확보
  • 도구 자동 생성 파이프라인 — 처리 못 한 요청을 모아 Structured Outputs(json_schema strict)로 도구 초안 생성 → 스키마 검증 → 자동 배포 · dry-run → 실패 누적 시 자동 비활성화
  • 개인정보 — 대화 저장 시 이름을 토큰으로 바꿔 저장하고 불러올 때 복원(타입당 SOQL 1회)
  • MCP 서버 — Apex REST로 MCP Streamable HTTP(initialize · tools/list · tools/call · resources)를 직접 구현, OAuth 보호 리소스 메타데이터(RFC 9728) 지원, AI 답변 안에 평가지 화면을 띄우는 MCP Apps(ui:// 리소스)
  • 쓰기 안전장치 — 쓰기 도구는 요약 → 사용자 확인 → 실행 2단계, 확인 단계 서명 검증(HMAC)
